# Работа с Genesis FinAudit

Команда — **Standout**. Финансовый контракт и воспроизводимость должны сохраняться при изменениях.

## Окружение

Python 3.11 и uv:

```bash
./scripts/setup
./scripts/dev fin-audit serve --port 8765
```

На macOS `scripts/dev` использует окружение в пользовательском cache, чтобы editable import не зависел от особенностей синхронизируемой папки Documents. На Linux используется `.venv`. Изменения shell profile не нужны.

## Проверки

```bash
./scripts/dev pytest -q
node --test tests/web_lesson.test.mjs tests/web_replay.test.mjs
```

Linux sandbox проверяется отдельно в подготовленном контейнере:

```bash
./scripts/verify --offline --context NAME
```

Host-прогон не доказывает OS-изоляцию. Не подменяйте ошибку secure-профиля запуском cooperative.

## Финансовая модель

1. Уточните публичную policy и схему.
2. Добавьте независимый пример с вручную проверяемыми суммами.
3. Проверьте генератор, truth-blind checker и scorer раздельно.
4. Сохраните корректность чистых split/partial/refund/repeated-amount случаев.
5. Проверьте взаимодействия, ID/order transforms и replay.

Эталон не должен становиться входом обычной политики или независимого checker. Не исправляйте неверный ответ перед оценкой. Изменение замороженного корпуса требует новой версии и manifest.

## Документация и коммиты

Для чисел в README указывайте версию и среду. Старый receipt относится к конкретному архиву, а не к последующим коммитам. После изменения интерфейса обновляйте реальные скриншоты и подписи.

В Git входят исходники, открытые данные и отобранные отчёты. `artifacts/`, `dist/`, закрытые seeds, credentials и временные browser sessions исключены. Не добавляйте их принудительно.

Описывайте в коммите изменение, причину и проверку. Не создавайте фиктивную историю этапов задним числом: первичная публикация импортирует уже существующий проект.
