# Интерактивный тренажёр

## Два понятных эксперимента в актуальных исходниках

На первом экране «Итог верный. Учёт — нет» показана открытая учебная книга: повторный счёт увеличивает выручку на50 000₸, неверный курс уменьшает её на50 000₸. Общий итог550 000₸ совпадает с документами, но внутри две отдельные ошибки. «Запустить аудитора» выполняет реальные скриптовые политики; после результата доступны доказательства и сравнение награды.

Второй эксперимент — «А что, если исправить?». После завершения исходной проверки оператор отдельно включает удаление дубля и восстановление курса. Сервер редактирует копию текущих публичных проводок и независимо проверяет её через checker. Получаются четыре состояния:550 000₸/2ошибки,500 000₸/1ошибка,600 000₸/1ошибка,550 000₸/0ошибок. Раскрывающийся список показывает фактически удалённые и исправленные записи. Первичные счета, котировки, исходная попытка, её бюджет и награда сохраняются.

Разбор ограничен основным открытым примером и доступен только после терминального ответа. Параметры API — два строгих boolean; загрузить собственную книгу или раскрыть разбор незавершённой попытки нельзя. Закрытый RL-протокол и функция награды не изменены. Эти изменения находятся в исходниках; ранее зафиксированный ZIP0.6.0 автоматически не обновляется.

Запуск из исходников после `./scripts/setup`:

```bash
./scripts/dev fin-audit serve --port 8765
```

Откройте http://127.0.0.1:8765/. Интерфейс и Python-сервер работают без интернета, Node, API-ключей и сторонних веб-библиотек. Сервер слушает только loopback и отдаёт пять фиксированных файлов интерфейса с ограниченным JSON API. Ctrl+C останавливает сервер; порт можно изменить.

Сохранённый релиз 0.6.0 включает более ранний интерфейс и лабораторию генерации в exact image и source inventory. Последний дизайн и интерактивные исправления выше добавлены после его фиксации; они требуют новой упаковки. Из распакованного старого пакета запускайте `./demo --offline --port 8765`; host Python-прокси связывается с сервером внутри контейнера через Docker exec, сохраняя `network=none`. В подготовленном image worker выбирает secure profile; fallback на cooperative отсутствует. Проверка пакета — `./verify --offline`. [Точная область прогонов и отчёты](VERIFICATION.md). Старый архив 0.5.0 сохраняется отдельно.

## Суть проекта и главный экран полигона

Genesis — среда для обучения и проверки ИИ-аудиторов. Генератор создаёт вымышленную компанию и первичные документы, затем вносит контролируемые ошибки. Агент получает публичные материалы через ограниченные инструменты; независимый оценщик проверяет каждую находку и выдаёт награду. Веса модели в этом проекте не обновляются; работающую среду демонстрируют скриптовые политики.

Главный экран показывает эксперимент «Две ошибки. Один правильный итог». Выручка 550 000 ₸ сохраняется, потому что повторное признание добавляет 50 000 ₸, а неверный курс убирает 50 000 ₸. За общей суммой нужно увидеть две отдельные доказуемые ошибки.

«Запустить расследование» выполняет два настоящих процесса на одной книге: `simple` и `silent`. Сервер возвращает результаты после завершения обоих. Далее интерфейс воспроизводит фактическую траекторию `simple`: задание, четыре чтения таблиц и submit. Это запись завершённого запуска, а не имитация рассуждений или обучения. Запись можно остановить, продолжить, выбрать конкретный шаг или сразу раскрыть вердикт. При reduced motion анимация пропускается.

После вердикта показаны доказанные находки и сравнение награды. На маскирующейся книге `silent` получает −1, `simple` — +0,992. На чистой книге пустой ответ корректен и получает +1, тогда как чтение инструментов немного снижает награду `simple`. Графики относятся к одному эпизоду, не являются кривыми обучения.

В «Лаборатории» можно выбрать любое подмножество четырёх семейств ошибок, включая пустое. Генератор создаёт новый случайный эпизод с новыми суммами, документами и ID. Настройки известны оператору лаборатории; seed, truth и provenance не передаются worker. После завершения доступны фактические доказательства и оценки обеих политик. Лабораторные повторы не заменяют исходный закрытый протокол проекта.

«Суть проекта» открывает краткую схему генератор → среда → агент → оценщик с явным указанием реализованных возможностей. Самостоятельная проверка и пошаговое обучение человека доступны ниже основного эксперимента.

## Первый запуск: «Разобрать вместе»

Начальный экран объясняет роль аудитора и показывает, какие материалы переданы на проверку. В кейсе «Итог сошёлся» доступны четыре шага:

1. Откройте первичный счёт и посмотрите сумму, валюту и дату.
2. Сравните сумму счёта с двумя записями в книге. Выберите размер расхождения. Неверный выбор вызывает объяснение; верный позволяет добавить ошибку вместе с доказательствами.
3. Сравните валютный счёт, курс на дату документа и оценку в книге. Выберите курс и добавьте второе расхождение.
4. Проверьте заключение и отправьте его настоящему оценщику.

Подсказки вычисляются только из публичной книги через `lesson.mjs`: приватные ответы не запрашиваются. Пошаговый урок ограничен открытым демонстрационным кейсом; неподдерживаемые книги и дробные оценки без точного целого результата не получают выдуманный разбор. Учебный режим явно отмечается в результате и в выгрузке JSON (`assistance=guided_lesson`), в том числе если пользователь затем переключился в самостоятельный режим.

## Самостоятельная проверка

1. Нажмите «Проверить документы самому» или выберите другой кейс. Доступны четыре фиксированные истории: маскирующиеся ошибки, распределение + курс, распределение + период, контрольная книга. Лаборатория дополнительно создаёт новые книги с выбранными семействами ошибок.
2. Начните со счетов и перейдите к записям в книге, платежам, курсам и правилам учёта. Поиск и фильтр помогают найти операцию. Название документа открывает детали и связанные записи.
3. Нажмите «Добавить ошибку вручную». Выберите тип, операцию и сумму. Связанные доказательства подставятся из публичных ссылок; их можно проверить и изменить в раскрывающемся разделе. Сумма и наличие ошибки остаются выводом пользователя. Доступны редактирование и удаление черновика.
4. Закончите проверку. Пустое заключение допустимо для корректной книги. Результат отдельно показывает доказанные ошибки, пропуски и неподтверждённые заявления. Кнопка «Понять ошибку» открывает объяснение, расчёт и документы.

Короткие названия «Счёт 1», «Запись 3» используются только для отображения. Сохранённые находки содержат оригинальные непрозрачные идентификаторы. Поля matching, точные суммы, ограничения до 10 доказательств и штрафы оценщика сохраняются.

Ручная попытка ограничена 30 минутами и 100 действиями. Начальное чтение таблиц проходит через `list_records` и учитывается в бюджете. Открытие счёта или платежа до окончания попытки вызывает `get_document`. Уже прочитанные записи доступны повторно в интерфейсе без нового действия. Эталон и статус каждой ошибки раскрываются только после терминального ответа.

Режим, шаг урока, ответы, вкладка, черновик и подборка доказательств восстанавливаются в той же вкладке через sessionStorage и непрозрачный токен. Попытки хранятся в памяти сервера, максимум 64 сессии; они удаляются после часа или остановки сервера. Повторы открытых учебных кейсов не считаются hidden evaluation.

## Пример для жюри

На главном экране нажмите «Запустить расследование»: два реальных worker, `simple` и `silent`, проверят одну книгу. В подготовленном image используется режим `secure`, при обычном запуске из исходников на хосте — `cooperative`. На вход передаются публичные документы и правила; oracle и эталон не передаются. После завершения экран воспроизводит фактические действия `simple`, показывает доказательства и сравнивает оценки. Доступный в ручном разборе отдельный запуск аудитора сохраняет оценку ручной попытки в JSON: предварительное открытие документов могло увеличить стоимость инструментов.

Скриптовый аудитор и учебные подсказки явно обозначены. Обученная LLM и независимый контрольный балл за разбор с подсказками не заявляются. Веб-запуск из исходников использует cooperative-процессы; проверку изоляции secure workers внутри exact image подтверждают отдельные Linux-тесты и внешний receipt текущего релиза.

В первом кейсе покажите две отдельные ошибки: повторный счёт добавил 50 000 ₸, неверный курс убрал 50 000 ₸. Итог 550 000 ₸ сохранился. В кейсе с валютным платежом покажите, как валютная оценка влияет на сумму нераспределённого остатка.

## Проверки

```bash
./scripts/dev pytest -q tests/test_web.py tests/test_web_readiness.py tests/test_demo.py tests/test_release.py
node --test tests/web_lesson.test.mjs tests/web_replay.test.mjs
```

Node нужен только для дополнительных development-проверок учебного модуля и записи действий. Браузер исполняет оба модуля непосредственно. При подготовке 0.6.0 все 11 Node-проверок повторно прошли; локальная запись — `artifacts/release-host-0.6.0/node-tests.txt`. Этот host receipt не заменяет Linux amd64 clean-run.

Историческая проверка интерфейса из исходников, итерация v2 от 20 ноября 2026:

- Полный Python-набор: 834 passed, 5 Linux security tests skipped на macOS. Веб-проверки: 13 passed.
- Учебный модуль: 8 passed, включая дату курса в часовом поясе компании, неизменность входа и отсутствие выдуманной связи при неизвестном назначении платежа.
- Подбор доказательств проверен на 6 реальных находках всех четырёх типов через production scorer. Обе находки учебного урока вместе принимаются с F1 = 1.
- В браузере пройдены четыре шага урока, неверные/верные ответы, восстановление прогресса, ручной валютный вывод с автоматическими документами, редактирование, ошибка формата суммы и результат с пропущенными/неподтверждёнными ошибками.

## Передаваемый полигон 0.6.0

`./demo --offline --port 8765 --context NAME` сначала проверяет manifest и все hashes, всегда загружает точный проверенный image archive и использует immutable image ID. Host и application слушают только loopback. Контейнер не публикует порты и не имеет сети; HTTP проходит через ограниченный Docker exec bridge. Ctrl+C останавливает только контейнер этого запуска.

G5 дополнительно запрашивает все пять assets по HTTP, проверяет отсутствие private gold до терминального ответа, новую чистую компанию и компанию с четырьмя ошибками, два действительных worker на каждой книге и нейтральный closed feedback. Результат `readiness/web-summary.json` связан hash-цепочкой с общим completed receipt. Текущие измерения и платформа — в [статусе 0.6.0](RELEASE_0_6_STATUS.md).
