# Genesis FinAudit: записка для проверки

**Что сдаём.** Воспроизводимую RL-среду для финансового аудита: генератор синтетических книг, инструменты расследования, независимый оценщик и записанные взаимодействия. Обновление весов модели не выполняется. Наши четыре reference adapters воспроизводят роли из кейса; это собственные реализации, а не предоставленные организаторами политики. Фактические результаты текущей сдачи и платформы фиксируются в [статусе 0.6.0](RELEASE_0_6_STATUS.md), а соответствие исходному кейсу — в [матрице требований](CONFORMANCE.md).

**Версии и воспроизводимость.** Программа 0.6.0, финансовая схема0.2, замороженный открытый корпус0.3, wire protocol1.0. Генерация разделяет случайность исходного мира, ошибок и представления. Одинаковые версии, seed, config и действия дают одинаковую финансовую книгу и логический transcript. Длительность выполнения измеряется отдельно. В репозитории находятся10 train и10 dev эпизодов с индексом и hashes; локальный holdout содержит20 других эпизодов:5 чистых,5 с взаимодействиями и10 прочих. Его конфигурации используют новые сочетания известных параметров, а не только новые seed. Индексы и seed доступны trusted runner, а не worker.

**Почему эталону можно доверять.** Сначала материализуется и проверяется чистая история; затем в неё вносятся причинные изменения. Отдельный truth-blind checker заново выводит *все* поддерживаемые расхождения только из public documents, policy и ledger. Он не импортирует mutation implementation и не принимает ожидаемые находки как вход. Сравнение выведенного набора с намеренными изменениями обнаруживает и пропущенные ошибки, и случайные побочные ошибки. Provenance объясняет историю, но сам по себе не доказывает правильность. Ручные fixtures и контрпримеры проверяют денежные расчёты отдельно от генератора.

Деньги хранятся целыми minor units; курсы — Decimal-строками. Все проводки оцениваются вKZT, исходная валюта и применённая оценка явно записаны в метаданных журнала. Каждый журнал сбалансирован. Поддерживаются exponent0/2/3, явные смещения времени и принадлежность периоду `[start,end)` в timezone компании. Законные повторные суммы, частичные/разбитые платежи, realised FX и документированные возвраты создаются и в чистых книгах. Связь с отсутствующим основанием не угадывается.

| Семейство | Канонический объект и сумма |
| --- | --- |
| Duplicate invoice | Все первичные AR-строки повторного признания одного счёта, включая исходную; превышение признанной суммы |
| Payment allocation | Payment ID и назначенный invoice ID; оставшаяся сумма наUNALLOCATED в наблюдаемой оценке платежа |
| FX | Одна первичная AR/CASH-строка; абсолютная разница наблюдаемой и нормативной оценки |
| Cutoff | Одна первичная AR/CASH-строка; абсолютная наблюдаемая сумма, попавшая в другой период |

Суммы этих семейств условны и не складываются в универсальный «ущерб». Например, исправление курса платежа изменяет и сумму его нераспределённого остатка. Обе зависимые пары — allocation+FX и allocation+cutoff — имеют проверяемые counterfactual repairs по публичным фактам. Отдельный [демонстрационный сценарий](DEMO_GUIDE.md) показывает две ошибки, скрытые совпадающим итогом550 000₸.

**Инструменты и оценка.** Агент видит начальное задание, manifest, краткую policy и бюджет; дальше получает только запрошенные records/documents или ограниченную ошибку. Доступны pagination≤50, адресация ID, арифметический calculator и submit. Максимум100 действий вместе с submit; proof содержит≤10 ID. Для зачёта нужны правильные тип, точный канонический affected set, валюта, сумма в опубликованном допуске и полный допустимый proof. Matcher использует максимальное взаимно однозначное сопоставление. Текст объяснения не повышает оценку. Common reward сохранён: `clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)`, с отдельным правилом−1 для структурно неверного ответа. Пустой ответ на чистой книге имеетF1=1.

**Граница изоляции.** Текущий release target — Linux amd64/Python3.11; фактическая проверка платформы и способ исполнения фиксируются во внешнем clean receipt точного tar.gz. Secure runtime использует отдельный worker, UID/chroot, seccomp, закрытые FD/environment, отсутствие сети и read-only books. Truth, provenance, seed и оценщик находятся снаружи worker jail. В closed режиме reward и diagnostics не возвращаются политике по ходу; завершённый отчёт публикуется после всего прогона. Cooperative developer mode не является свидетельством OS-изоляции. Исторический релиз 0.5.0 проверен на Linux ARM64 и сохранён отдельно. Для ARM-хоста с full-system QEMU явно указываются cross-architecture границы; точные resource/cold-transfer measurements см. в актуальном receipt. До появления внешнего completed receipt новый amd64-пакет не считается прошедшим чистую передачу.

**Как проверять.** В распакованном `bundle/` одна команда: `./verify --offline`. В исходном checkout используется `./scripts/verify --offline`. Проверяются входные hashes, выполняются тесты, общий протокол, showcase и объявленный mutation suite; провал даёт nonzero. Траектории сохраняют обязательные поля и повторяются через ту же среду. Двенадцать mutation cases проверяют реальные временные копии оценщика: исключения импорта и тайм-ауты не засчитываются как обнаружение смысловой ошибки. Это конечный набор faults, не доказательство отсутствия любых дефектов.

**Границы модели.** Это синтетическая дебиторская модель: KZT как база, одна foreign currency на эпизод, settlement в валюте счёта, atomic receipt, native credit-note refund. Полнота checker относится к этой опубликованной модели. Имена добавляются опциональным расширением `names-1.0`; оно меняет только display labels и сохраняет bytes замороженного корпуса0.3. Пригодность для реального аудита, улучшение обученной модели и официальный балл не заявляются. Официальные fixed tests/adapters и канал подачи не предоставлены; известный дедлайн из сохранённого кейса —22 ноября2026,23:59 Астана,UTC+05:00.


**Интерактивное демо в том же пакете.** `./demo --offline` запускает точный проверенный image, его web assets и secure workers. Host-stdlib proxy передаёт HTTP через Docker exec при `network=none`, без published container ports. Лаборатория создаёт новые синтетические книги с выбранными семействами; запись действий и сравнение simple/silent — фактические завершённые worker runs. Открытая конфигурация лаборатории и подсказки не выдаются за закрытую оценку; обучение весов не заявляется.
